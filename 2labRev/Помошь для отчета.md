### 4. Конфигурация веб-сервера Apache2

* **Символическая ссылка:** `/var/www/redmine` → `/home/redmine/redmine-4.0.5/public`
* **Конфигурационный файл виртуального хоста:** `/etc/apache2/sites-available/master.conf`
  ```apache
  <VirtualHost *:80>
      ServerAdmin admin@redmine.ru
      ServerName proj.ru
      DocumentRoot /var/www/

      <Directory /var/www/redmine>
          AllowOverride All
          Options FollowSymLinks
          RailsEnv production
          PassengerAppRoot /home/redmine/redmine-4.0.5
          PassengerBaseURI /redmine
          Options -MultiViews
          Require all granted
      </Directory>

      RedirectMatch ^/$ /redmine/

      ErrorLog ${APACHE_LOG_DIR}/error.log
      CustomLog ${APACHE_LOG_DIR}/access.log combined
  </VirtualHost>
  ```
* **Активированные модули и конфигурации:**
  * Модуль: `passenger` (`sudo a2enmod passenger`)
  * Сайт: `master.conf` (`sudo a2ensite master.conf`)
  * Отключён дефолтный хост: `000-default.conf` (`sudo a2dissite 000-default.conf`)

### Скрипт 1: `install.sh`
**Назначение:** Полное нативное развёртывание стека (PostgreSQL 14, Redmine 5.0.9, Apache 2.4, Phusion Passenger, тема Purplemine2, локальный Git).  
**Запуск:** `bash ~/install.sh`

```bash
#!/bin/bash
set -e

# 1. Пакеты ОС
sudo apt update -qq
sudo apt install -y -qq mc gcc make zlib1g zlib1g-dev libssl-dev libyaml-dev \
  libcurl4-openssl-dev ruby ruby-dev libapache2-mod-passenger apache2 apache2-dev \
  libapr1-dev libxslt1-dev libxml2-dev libmagickwand-dev imagemagick \
  postgresql postgresql-contrib libpq-dev git rsync curl

# 2. Настройка PostgreSQL
sudo systemctl start postgresql
sudo systemctl enable postgresql
cd /tmp
sudo -u postgres psql -tc "SELECT 1 FROM pg_database WHERE datname = 'redmine'" | grep -q 1 || \
  sudo -u postgres psql -c "CREATE DATABASE redmine WITH ENCODING='UTF8' OWNER=postgres;"
sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD 'postgres';"

CONF=$(sudo find /etc/postgresql/ -name "pg_hba.conf" | head -n 1)
sudo sed -i 's/local   all             postgres                                peer/local   all             postgres                                trust/' "$CONF"
sudo sed -i 's/local   all             all                                     peer/local   all             all                                     trust/' "$CONF"
if ! sudo grep -q "host redmine postgres 127.0.0.1/32 trust" "$CONF"; then
    echo "host redmine postgres 127.0.0.1/32 trust" | sudo tee -a "$CONF"
fi
sudo systemctl restart postgresql

# 3. Исходники Redmine и зависимости
sudo mkdir -p /home/redmine
cd /home/redmine
if [ ! -d "/home/redmine/redmine-4.0.5" ]; then
    sudo wget -q https://www.redmine.org/releases/redmine-5.0.9.tar.gz
    sudo tar -xzf redmine-5.0.9.tar.gz
    sudo mv redmine-5.0.9 redmine-4.0.5
    sudo rm -f redmine-5.0.9.tar.gz
fi

cd /home/redmine/redmine-4.0.5
sudo tee config/database.yml > /dev/null << 'DB_CONF'
production:
  adapter: postgresql
  database: redmine
  host: 127.0.0.1
  username: postgres
  password: "postgres"
  encoding: utf8
DB_CONF

if ! sudo grep -q 'require "logger"' config/boot.rb; then
    sudo sed -i '1i require "logger"' config/boot.rb
fi

sudo gem install bundler --no-document > /dev/null 2>&1 || true
sudo bundle config set --local without 'development test'
sudo bundle install

sudo bundle exec rake generate_secret_token
sudo RAILS_ENV=production bundle exec rake db:migrate
echo "ru" | sudo env RAILS_ENV=production REDMINE_LANG=ru bundle exec rake redmine:load_default_data 2>/dev/null || true

# 4. Тема оформления Purplemine2
sudo mkdir -p /home/redmine/redmine-4.0.5/public/themes
if [ ! -d "/home/redmine/redmine-4.0.5/public/themes/purplemine2" ]; then
    sudo git clone -q https://github.com/mrliptontea/PurpleMine2.git /home/redmine/redmine-4.0.5/public/themes/purplemine2
fi
sudo chown -R www-data:www-data /home/redmine/redmine-4.0.5
sudo chmod -R 755 /home/redmine/redmine-4.0.5

# 5. Веб-сервер Apache2 + Passenger
sudo rm -f /var/www/redmine
sudo ln -s /home/redmine/redmine-4.0.5/public /var/www/redmine

sudo tee /etc/apache2/sites-available/master.conf > /dev/null << 'APACHE_CONF'
<VirtualHost *:80>
    ServerAdmin admin@redmine.ru
    ServerName proj.ru
    DocumentRoot /var/www/

    <Directory /var/www/redmine>
        AllowOverride All
        Options FollowSymLinks
        RailsEnv production
        PassengerAppRoot /home/redmine/redmine-4.0.5
        PassengerBaseURI /redmine
        Options -MultiViews
        Require all granted
    </Directory>

    RedirectMatch ^/$ /redmine/

    ErrorLog ${APACHE_LOG_DIR}/error.log
    CustomLog ${APACHE_LOG_DIR}/access.log combined
</VirtualHost>
APACHE_CONF

sudo a2enmod passenger > /dev/null 2>&1
sudo a2dissite 000-default.conf > /dev/null 2>&1 || true
sudo a2ensite master.conf > /dev/null 2>&1
sudo systemctl restart apache2

# 6. Репозиторий Git
mkdir -p ~/project
cd ~/project
if [ ! -d ".git" ]; then
    git init
    git config user.name "cropsi"
    git config user.email "cropsi@guap.ru"
    echo "# Project Documentation" > README.md
    git add .
    git commit -m "Initial commit: Redmine infrastructure setup"
fi
```

### Скрипт 3: `check_all.sh`
**Назначение:** Комплексная автоматическая верификация готовности стенда (проверка PostgreSQL, Apache2, Passenger, отсутствия Docker, базы данных, 15 задач, HTTP-ответа и Git).  
**Запуск:** `bash ~/check_all.sh`

```bash
#!/bin/bash
echo "=================================================="
echo "    ПРОВЕРКА ГОТОВНОСТИ СТЕНДА ЛАБОРАТОРНОЙ №2    "
echo "=================================================="

echo -n "[1] Служба PostgreSQL: "
if systemctl is-active --quiet postgresql; then echo "OK (работает)"; else echo "FAIL"; fi

echo -n "[2] Служба Apache2: "
if systemctl is-active --quiet apache2; then echo "OK (работает)"; else echo "FAIL"; fi

echo -n "[3] Модуль Passenger в Apache: "
if apache2ctl -M 2>/dev/null | grep -q "passenger"; then echo "OK (загружен)"; else echo "FAIL"; fi

echo -n "[4] Проверка отсутствия Docker-контейнеров: "
if command -v docker >/dev/null 2>&1 && docker ps -q 2>/dev/null | grep -q .; then
    echo "ВНИМАНИЕ (запущены контейнеры docker!)"
else
    echo "OK (чистая нативная система без Docker)"

echo -n "[5] Тема Purplemine2 в файловой системе: "
if [ -d "/home/redmine/redmine-4.0.5/public/themes/purplemine2" ]; then echo "OK (установлена)"; else echo "FAIL"; fi

echo -n "[6] База данных PostgreSQL 'redmine': "

if sudo -u postgres psql -lqt | cut -d \| -f 1 | grep -qw redmine; then echo "OK (существует)"; else echo "FAIL"; fi

echo -n "[7] Проект в Redmine (supermarket-36): "
PROJ=$(sudo -u postgres psql -d redmine -tAc "SELECT identifier FROM projects WHERE identifier='supermarket-36';" 2>/dev/null)
if [ "$PROJ" = "supermarket-36" ]; then echo "OK (найден: $PROJ)"; else echo "FAIL"; fi

echo -n "[8] Участники проекта (student_a, b, c): "

if [ "$MEMBERS" -ge 3 ]; then echo "OK (найдено участников: $MEMBERS)"; else echo "FAIL (найдено: $MEMBERS)"; fi

echo -n "[9] Задачи бэклога в проекте: "
ISSUES=$(sudo -u postgres psql -d redmine -tAc "SELECT count(*) FROM issues;" 2>/dev/null)
if [ "$ISSUES" -ge 15 ]; then echo "OK (создано задач: $ISSUES)"; else echo "FAIL (задач: $ISSUES)"; fi

echo -n "[10] Ответ веб-сервера (HTTP): "
HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1/redmine)
if [ "$HTTP_CODE" = "200" ] || [ "$HTTP_CODE" = "302" ]; then
    echo "OK (HTTP $HTTP_CODE)"
else
    echo "FAIL (HTTP $HTTP_CODE)"
fi

echo -n "[11] Локальный Git-репозиторий: "
if [ -d "$HOME/project/.git" ]; then echo "OK (~/project готов)"; else echo "FAIL"; fi

echo "=================================================="
echo " Адрес в браузере: http://$(hostname -I | awk '{print $1}')/redmine"
echo "=================================================="
```

### Скрипт 5: `setup_gitflow.sh`
**Назначение:** Создание системных пользователей Linux (`student_a`, `student_b`, `student_c`, `gitservice`), инициализация центрального bare-репозитория `/srv/supermarket36/repository.git` и автоматическое воспроизведение модели Git Flow (ветки `main`, `develop`, feature-ветки, моделирование и разрешение учебного merge-конфликта, создание релизного тега `v1.0.0` для отчёта).  
**Запуск:** `bash ~/setup_gitflow.sh`

```bash
#!/bin/bash
set -e

# 1. Системные пользователи
sudo groupadd -f supermarket36
for u in student_a student_b student_c; do
    if ! id -u "$u" >/dev/null 2>&1; then
        sudo useradd -m -s /bin/bash -g supermarket36 "$u"
        echo "$u:student123" | sudo chpasswd
    fi
done

if ! id -u gitservice >/dev/null 2>&1; then
    sudo useradd -r -s /bin/bash -g supermarket36 -d /srv/supermarket36 gitservice
fi

# 2. Общий Bare-репозиторий
sudo mkdir -p /srv/supermarket36/repository.git
sudo chown -R gitservice:supermarket36 /srv/supermarket36
sudo chmod -R 2770 /srv/supermarket36

cd /srv/supermarket36/repository.git
sudo -u gitservice git init --bare --shared=group

# 3. Моделирование веток и коммитов Git Flow
WORK_DIR=$(mktemp -d)
cd "$WORK_DIR"
git clone /srv/supermarket36/repository.git client_repo
cd client_repo

git config user.name "Роман Кочетков"
git config user.email "student_a@guap.ru"

# Ветка main
echo "# Supermarket 36 System" > README.md
git add README.md
git commit -m "docs: исходное состояние учебного примера"
git branch -M main
git push origin main

# Ветка develop
git checkout -b develop
echo "## Development baseline" >> README.md
git commit -am "docs: ветка develop"
git push origin develop

# Ветка feature student_b
git checkout -b codex/feature/SM-05-review
echo "Requirement review passed by student_b" >> README.md
git commit -am "docs: ветка проверки требований"
git push origin codex/feature/SM-05-review

# Ветка feature student_a (создание конфликта)
git checkout develop
git checkout -b codex/feature/SM-06-process
echo "Process configuration applied by student_a" >> README.md
git commit -am "docs: ветка настройки процесса"
git push origin codex/feature/SM-06-process

# Слияние первой ветки
git checkout develop
git merge --no-ff codex/feature/SM-05-review -m "merge: результат проверки"

# Слияние второй ветки с разрешением конфликта
git merge codex/feature/SM-06-process || true
echo -e "# Supermarket 36 System\n## Development baseline\nRequirement review passed by student_b\nProcess configuration applied by student_a" > README.md
git add README.md
git commit -m "merge: согласованное разрешение конфликта"
git push origin develop

# Релиз в main и тег v1.0.0
git checkout main
git merge --no-ff develop -m "release: учебный выпуск"
git tag -a v1.0.0 -m "Выпуск версии 1.0.0"
git push origin main --tags

rm -rf "$WORK_DIR"
echo "=== Git Flow модель успешно воспроизведена ==="
```
