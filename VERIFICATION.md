## Исправления при повторной проверке

Ошибки find/sort теперь останавливают docforge до изменения документов. В BPMN добавлена схема расположения. Redmine получил автоматическую настройку, правильный для версии 6 путь themes, стабильный SECRET_KEY_BASE и проверку конфигурации. Серверные тесты проверяют совпадение подключений API и администратора с одной тестовой БД. Титульные данные и распределение ролей персонализированы.

## Ограничения фактического запуска

**FastAPI-контейнеры ЛР2 и ЛР3 не собраны:** официальный PyPI и проверенные HTTPS-зеркала отвечают таймаутом соединения/TLS. Поэтому полный запуск db → bootstrap → api → nginx через Compose не подтверждён. Ошибка возникает на pip install до выполнения кода приложения. Проверка сертификатов не отключалась. Функциональность API проверена отдельно на Windows; схема PostgreSQL и сборка клиента проверены также в Linux Docker.

Docker Hub тоже отвечал таймаутом. Базовые официальные образы получены из публичного кэша Google mirror.gcr.io и сохранены под штатными локальными тегами. [Описание кэша Google](https://docs.cloud.google.com/artifact-registry/docs/pull-cached-dockerhub-images). Пользовательские образы, контейнеры и тома не удалялись; настройки Docker не сбрасывались.

VirtualBox VM по пошаговым рисункам методички не создавалась. Linux-проверки выполнены в WSL 2; отдельный вариант VirtualBox описан в VM_SETUP.md. Подписи, оценку преподавателя и личную коллективную защиту автоматическая проверка не заменяет. Группа и преподаватель оставлены пустыми.

## Свидетельства и повторение

ЛР2: evidence/redmine-issues.png, redmine-members.png, redmine-checks.json; provision_users.sh, verify_git.sh, redmine/verify.rb. ЛР3: evidence/backend-tests.txt, frontend-tests.txt, frontend-build.txt, catalog-benchmark.json, large-dataset.txt, explain.txt, restore-check.txt, catalog-desktop.png и catalog-mobile.png. ЛР4: evidence/linux-checks.txt.

После восстановления доступа к PyPI: из 2lab выполнить `bash setup.sh --with-redmine`; из 3lab — `bash setup.sh` и `bash verify.sh`. verify.sh создаёт отдельный временный проект и не удаляет прикладные данные.

HTTP-измерения относятся к прогретому локальному FastAPI без Nginx, HTTPS и VM; они не подтверждают все эксплуатационные NFR на другом оборудовании. Клиент загружает одну страницу. Первые Windows-тесты использовали порт 55436; после его резервирования Hyper-V повтор выполнен на 127.0.0.1:25436. Существующая пользовательская БД не изменялась.
