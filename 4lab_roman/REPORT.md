# Генерация и обработка документов средствами Bash

Индивидуальная работа: Кочетков Роман. Вариант 12.

## 1 Назначение утилиты и постановка задачи

Разработана утилита `docforge` по варианту 12. Она формирует текстовые файлы, находит документы по расширению, объединяет найденное содержимое, выполняет буквальную замену фрагментов текста, переименовывает файлы и расширения, удаляет документы в локальную корзину и восстанавливает их. Предметные примеры относятся к супермаркету, но функции не привязаны к схеме его БД.

Работа выполняется индивидуально. Программные модули ЛР №3 не копируются в эту работу. Утилита написана на Bash и вызывает find/awk/coreutils; она не является оболочкой над Python-приложением.

## 2 Зависимости и установка

Требуются Linux, Bash 4.4+, GNU coreutils (`realpath`, `mktemp`, `mv`, `cat`, `sort`, `tr`, `wc`, `chmod`, `install`), GNU findutils (`find`) и awk. GNU-опции `-print0`, `-printf`, `sort -z`, `realpath -m`, `chmod --reference` являются частью выбранной платформы. Поддержку BSD/macOS без GNU-утилит нельзя предполагать.

Установка: `sudo apt install bash coreutils findutils gawk`; затем `sudo bash install.sh`. Скрипт копирует утилиту в `/usr/local/bin/docforge` с 0755. Это требуемое методичкой имя без расширения. Исходник остаётся в директории лабораторной для проверки и сопровождения. Перед обновлением установленной версии можно сохранить её копию и сравнить `--version`.

## 3 Структура сценария

Применены элементы шаблона методички: `#!/usr/bin/env bash`, `set -Eeuo pipefail`, определение script_dir, функции usage/msg/cleanup, обработчики EXIT/INT/TERM/ERR и разбор аргументов case. Справка и версия доступны без рабочего каталога. Сообщения об операции направляются в stderr, а результат `list` и ID удаления — в stdout, чтобы их можно было использовать конвейером или подстановкой команды.

`set -e` завершает сценарий при необработанной ошибке, `-u` обнаруживает неопределённую переменную, pipefail учитывает сбой внутри конвейера. Это не заменяет явные проверки аргументов. Временный результат создаётся в уникальном каталоге `.docforge-tmp/run.*`; trap удаляет только этот проверенный каталог. Удаление пользовательского документа выполняется перемещением в `.docforge-trash`, а не rm.

Таблица 1 — Разработанные функции

| Функция | Назначение | Важное свойство |
|---|---|---|
| usage | Справка по параметрам и командам | Работает без root и без установки |
| msg / die | Диагностика и завершение | stdout остаётся машинно-читаемым |
| safe_path | Нормализация пути и проверка границы root | Запрещает абсолютные пути, `..`, ссылки и служебные каталоги |

| validate_ext | Проверка расширения | Только 1–12 ASCII-букв/цифр |
| check_output | Защита существующего результата | Перезапись create/merge только с --force |
| scan / scan_checked | Поиск GNU find с NUL-разделителем, сортировкой и проверкой кода завершения | При неполном поиске отменяет операцию до изменения документов |
| check_text | Проверка отсутствия NUL | Не выполняет текстовую замену в бинарном файле |
| prepare_temp / commit_output | Подготовка результата и атомарная замена файла | Исходный файл сохраняется при ошибке формирования |

## 4 Расширенная справка

Общий синтаксис: `docforge --root DIRECTORY [--force] [--dry-run] COMMAND ARGS`. Все опции задаются перед командой. `--root` должен существовать; сама утилита не создаёт произвольную иерархию каталогов. Пользователь заранее создаёт нужные подкаталоги `mkdir -p`. Пути внутри операций относительные, кавычки сохраняют пробелы.

Таблица 2 — Подкоманды

| Команда | Аргументы | Результат |
|---|---|---|
| create | FILE TEXT | Файл с текстом и завершающим LF |
| list | Необязательный EXT | Относительные пути найденных файлов |
| merge | OUTPUT EXT | Сортированные входные файлы с разделителями-именами; сам OUTPUT исключён |
| replace | FILE OLD NEW | Все буквальные совпадения OLD заменены на NEW |
| rename | FILE NEW_BASENAME | Новое имя в том же каталоге, включая явное расширение |
| extension | OLD_EXT NEW_EXT | Массовая смена суффикса; до начала проверяются все коллизии |
| delete | FILE | Файл перенесён в корзину; stdout содержит уникальный ID |
| restore | ID DESTINATION | Содержимое восстановлено в незанятый путь |

`--dry-run` проверяет условия и выводит план без записи. Для `list` это эквивалентно обычному чтению. `--force` применяется только к create/merge; rename/restore/extension не перезаписывают существующие имена. Код 0 — успех, 2 — неправильные аргументы или нарушение ограничений, 1 — системная ошибка. INT/TERM завершают работу кодами 130/143.

При replace строка поиска непустая; OLD и NEW однострочные, воспринимаются буквально. Символы `&`, `$`, скобки и обратные слеши не превращаются в регулярные выражения или команды. Алгоритм awk на каждом шаге ищет index, выводит неизменённый префикс и замену, затем продолжает с оставшейся строкой; вставленный текст не сканируется повторно. Пустая замена разрешена. Результат нормализует окончание последней строки до LF.

## 5 Ограничения и устойчивость

Утилита рассчитана на текст UTF-8, имена с пробелами и кириллицей, но не на имена с переводами строк. Символические ссылки не обходятся. Сбой find или sort прерывает операцию: список сначала сохраняется во временный файл вне рабочего каталога и проверяется, затем используется. Даже dry-run может создать такой служебный файл, который удаляется при выходе; пользовательские документы не изменяются. Проверка пути защищает от случайного выхода за root; каталог не должен одновременно изменяться недоверенным процессом, поскольку проверка и перемещение не являются защищёнными ядром операциями openat. Одновременный запуск изменяющих команд по одним файлам не поддерживается.

Объединение читает данные потоково через cat и не загружает всё содержимое в память; список путей хранится в Bash-массиве, поэтому память растёт с числом файлов. Массовая смена расширения предварительно проверяет коллизии; сбой диска между несколькими mv может оставить часть имён изменёнными, общей файловой транзакции здесь нет. Одиночное редактирование формирует временный файл и заменяет его только после успешной записи.

Постоянное удаление из корзины не реализовано: задача удаления выполняется обратимым перемещением, а дальнейший срок хранения задаёт пользователь. Восстановление не заменяет существующий документ. При наличии жёстких ссылок редактирование создаёт новое содержимое по выбранному имени, а остальные ссылки продолжают указывать на старый inode.

## 6 Тестирование

`tests/test_docforge.sh` проверяет создание документа с пробелами и кириллицей, буквальную замену, объединение, исключение собственного output, dry-run, предварительное обнаружение коллизий, корзину, восстановление, переименование, смену расширений, запрет выхода через `..`, абсолютного пути и symlink, запрет пустого поиска, отказ от неявной перезаписи, бинарного ввода и частичного результата find.

Команды воспроизведения: `bash -n docforge`, `bash tests/test_docforge.sh`. Тест выполняется во временном каталоге. На Git Bash, если ln эмулирует ссылку копированием, проверка symlink явно отмечается SKIP; в Linux должна пройти без пропуска. Фактические результаты текущей проверки находятся в `../VERIFICATION.md`.

## 7 Выводы

1. Команды ОС можно объединить в специализированный инструмент с проверяемым контрактом.
2. Безопасная обработка имён требует кавычек, NUL-разделителей и проверки нормализованных путей.
3. Справка, диагностические коды, dry-run и временные файлы делают сценарий пригодным для повторного использования.
4. Смена расширения не является конвертацией формата, а несколько файловых операций не образуют общую транзакцию.

## 8 Исходный код и источники

Полный исходный код — файл `docforge`, установка — `install.sh`, автоматические проверки — `tests/test_docforge.sh`; это приложения к отчёту. Основание: методичка ЛР №4 (2021), с. 9–15, 18, 20. Дополнительные источники: `man bash`, `man find`, `man awk`, `man realpath`, `man mktemp`, `man mv`, установленные вместе с выбранной Linux-системой.

## 9 Подготовка к индивидуальной защите

Показать установленную команду `command -v docforge`, затем справку и версию. Создать отдельный каталог демонстрации с двумя файлами. Показать поиск, объединение, изменение текста и расширения, после чего удалить один файл и восстановить его по ID. Выполнить dry-run и сравнить состояние каталога до и после: файл не должен измениться. В конце показать ожидаемый отказ при попытке использовать `../` и существующее выходное имя без --force.

На вопрос о роли find пояснить, что он выполняет рекурсивный отбор обычных файлов по расширению; -prune исключает рабочую корзину и временные результаты. Разделитель NUL безопаснее обычного перевода строки при передаче путей между командами. Сортировка обеспечивает воспроизводимый порядок объединения. Сам результирующий файл исключён явно, иначе повторная сборка включала бы предыдущий отчёт в новый.

На вопрос о безопасности replace объяснить отличие буквальной подстроки от регулярного выражения. Данные передаются awk через переменные окружения, не вставляются в текст программы и не вычисляются оболочкой. Поэтому специальные символы текста не превращаются в выполняемые команды. Однако это не делает утилиту средством обработки файлов в конкурентном недоверенном каталоге: такая модель угроз требует других системных интерфейсов.

На вопрос об ошибках пояснить, почему trap удаляет временный результат, но не оригинал. Формирование текста завершается до mv, и неудачная генерация оставляет исходный документ. Массовое переименование проверяет известные коллизии заранее, однако отказ файловой системы в середине набора может дать частичное выполнение. Это ограничение надо объяснять прямо, не называя несколько mv транзакцией.

Доклад занимает 3–5 минут: назначение, зависимости, алгоритм двух ключевых операций, демонстрация ошибки и вывод. Участник должен уметь объяснить каждую вызываемую команду и показать границу рабочего каталога. Установка в /usr/local/bin позволяет вызывать утилиту из любого каталога; отсутствие расширения относится к имени установленной команды, а не к языку её реализации.

## 10 Выполненная Linux-проверка

08.09.2026 сценарий выполнен в Ubuntu 24.04.1 WSL 2 без пропусков. Проверены настоящая символическая ссылка и искусственный отказ find после частичного вывода. При таком отказе команды merge и extension возвращают ошибку и сохраняют исходные документы. Утилита установлена в /usr/local/bin/docforge с правами 0755 и владельцем root; command -v и --version подтверждают установку.

Результат относится к индивидуальной работе Кочеткова Романа. Git Bash-проверка из первоначального протокола дополнена настоящим Linux-запуском, поэтому ограничение SKIP для символических ссылок снято.
