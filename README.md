## 🚀 Быстрый запуск

### Предварительные требования
- Docker Engine 24+ & Docker Compose v2
- Node.js 18+ (для локальной сборки фронтенда при необходимости)
- Python 3.11+ (для локального запуска бэкенда)

---

### Этап 2: Стенд управления проектом и Redmine

Поднимает отдельный изолированный контур Redmine 6.1 и проверочный Nginx/API:

```bash
cd 2lab

# Проверка окружения и генерация конфигурации (.env)
bash setup.sh --check

# Запуск стенда вместе с Redmine
bash setup.sh --with-redmine
```

- **Диагностический стенд:** [http://localhost:8082](http://localhost:8082)
- **Веб-интерфейс Redmine:** [http://localhost:8085](http://localhost:8085)
- Локальные секреты сохраняются в `2lab/.env` (не подлежат фиксации в VCS).

---

### Этап 3: Основное приложение ИС супермаркета

Запускает полную систему: базу данных PostgreSQL 15, FastAPI бэкенд и React фронтенд:

```bash
cd 3lab

# Генерация .env и запуск контейнеров
bash setup.sh
```

После старта контейнеров доступны:
- **Веб-приложение (Кассовый узел и каталог):** [http://localhost:8083](http://localhost:8083)
- **Интерактивная документация Swagger / OpenAPI:** [http://localhost:8083/api/docs](http://localhost:8083/api/docs)
- **Healthcheck бэкенда:** [http://localhost:8083/api/health](http://localhost:8083/api/health)

#### Роли пользователей в приложении:
1. `cashier` — кассир (поиск товаров, добавление в корзину, сканирование штрих-кодов, проведение оплаты наличными/картой, печать чека).
2. `manager` — управляющий (управление номенклатурой товаров, ценами, остатками и категориями).
3. `auditor` — аудитор (просмотр журнала операций, истории чеков и аналитических срезов).

*Пароли генерируются при первом запуске в файле `3lab/.env`.*

#### Запуск тестов ЛР №3:
```bash
# Тесты бэкенда (pytest)
docker compose exec backend pytest

# Тесты фронтенда (Vitest)
docker compose exec frontend npm test
```

## 🌿 Модель ветвления (Git Flow)

В проекте реализована строгая модель **Git Flow**:
- `main` — стабильные релизные версии, готовые к сдаче.
- `develop` — интеграционная ветка разработки.
- `feature/<название>` — тематические ветки участников (`feature/SM-01-requirements`, `feature/SM-04-docker`).
- `feature/conflict-a` / `feature/conflict-b` — демонстрация возникновения и ручного разрешения конфликта слияния в `status.txt`.
- `release/1.0.0` — ветка подготовки первого релиза, зафиксированная аннотированным тегом `v1.0.0`.

Для визуализации дерева слияний выполните:
```bash
git log --graph --oneline --decorate develop feature/SM-01-requirements feature/SM-04-docker feature/conflict-a feature/conflict-b release/1.0.0
```

Графический снимок дерева сохранён в: [`2lab/evidence/git-flow-graph.png`](2lab/evidence/git-flow-graph.png).
