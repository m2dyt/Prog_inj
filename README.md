# Основы программной инженерии — четыре лабораторные

ЛР №1–3: вариант **36 — «Информационная система супермаркета»**. ЛР №4: вариант **12 — генерация и обработка документов**. Согласованный стек: React + JavaScript, Python + FastAPI, PostgreSQL. Отчёты и документация — на русском языке.

| Каталог | Содержание и граница этапа | Начать с |
|---|---|---|
| `1lab` | Концепция, спецификация, правила, CRUD, UML/BPMN/ER, архитектура. Только проектирование, без реализации | [README](1lab/README.md), [отчёт Word](1lab/REPORT_LR1.docx) |
| `2lab` | Linux VM, роли команды, Redmine, 15 задач CSV, Git Flow, Compose и технические заглушки | [README](2lab/README.md), [отчёт Word](2lab/REPORT_LR2.docx) |
| `3lab` | Реализация требований: PostgreSQL, FastAPI, React, тесты, отдельный стенд и большой набор данных | [README](3lab/README.md), [отчёт Word](3lab/REPORT_LR3.docx) |
| `4lab` | Самостоятельная Bash-утилита `docforge`: создание, поиск, объединение, замена текста, переименование, расширения, корзина | [README](4lab/README.md), [отчёт Word](4lab/REPORT_LR4.docx) |

Директории отражают последовательные результаты работ. ЛР №1 не содержит исходников приложения. ЛР №2 запускается независимо: её API проверяет только готовность среды, а страница обозначает технический стенд. Код каталога, кассы и схемы предметной области находится только в ЛР №3. Стенды №2 и №3 имеют разные Compose-проекты, порты и тома PostgreSQL. ЛР №4 не подменяет собой развёртывание приложения.

## Запуск

Целевая среда сценариев — Linux VM, описанная в ЛР №2. Для просмотра исходников достаточно редактора; PlantUML уже дополнен готовыми SVG/PNG.

```bash
cd 2lab
bash setup.sh --with-redmine
# Технический стенд: http://localhost:8082, Redmine: http://localhost:8085
```

```bash
cd 3lab
bash setup.sh
# Приложение: http://localhost:8083, OpenAPI: http://localhost:8083/api/docs
```

Пароли генерируются локально в `.env`; учётные записи приложения: `manager`, `cashier`, `auditor`. Значения паролей брать из соответствующих переменных этого файла. `.env` не включать в Git. Перезапуск сохраняет данные в томах. В контейнеры ЛР №3 загружаются 16 демонстрационных товаров; массовый набор создаётся отдельно в тестовой БД.

```bash
cd 4lab
bash tests/test_docforge.sh
sudo bash install.sh
docforge --help
```

## Отчёты и защита

В каждой работе есть редактируемый `REPORT_LR*.docx` с титульным листом, заданием, оглавлением, основным текстом и приложениями. На титульных листах внесены Кочетков Роман, Энгельгард Кирилл и Прохоров Максим; в ЛР4 только Кочетков Роман. Группа, преподаватель, даты и подписи остаются для заполнения. Обозначения A/B/C соответствуют участникам в указанном порядке.

Методички задают содержание работ; согласованная замена стека и последовательность выдачи кода применены по прямому указанию пользователя. Оригинальные PDF не изменялись. Указанные в документации номера страниц относятся к страницам соответствующих PDF.

Фактически выполненные проверки, измерения и ограничения воспроизведения перечислены в [VERIFICATION.md](VERIFICATION.md). В Ubuntu WSL 2 реально созданы четыре Linux-учётные записи и проверен Git Flow. Redmine работает на http://127.0.0.1:8085; скриншоты входят в ЛР2. Docforge установлен в Ubuntu. Сборка Python-контейнеров пока ограничена недоступностью PyPI; подробности и повторные команды — в VERIFICATION.md. Отдельная VirtualBox VM не создавалась.
