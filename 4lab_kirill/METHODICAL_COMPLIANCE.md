# Проверка по методическим указаниям ЛР №4

ЛР №4 индивидуальная, исполнитель — **Энгельгард Кирилл**, группа **4434**.  
**Вариант 6** (с. 18 методических указаний):  
*«Конфигурирование сетевых настроек операционной системы.  
Утилита должна реализовывать следующий функционал:  
— задание адресации, маски и шлюза на каждый сетевой интерфейс (работа с файлом `/etc/network/interfaces`);  
— задание статических маршрутов (при перезагрузке машины должны продолжать работать);  
— создание сетевого моста на сетевой интерфейс;  
— включение и отключение сетевых интерфейсов и сетевых мостов;  
— справочная информация (функция `usage()`) по использованию утилиты.»*

| Требование методических указаний | Где и как реализовано в работе |
|---|---|
| **Язык командной оболочки Bash** | Сценарий `netconfig`, синтаксис Bash 4.4+, GNU coreutils |
| **Следование шаблону сценария (раздел 2, с. 8–15)** | `set -Eeuo pipefail`, перехват сигналов `trap cleanup`, функции `usage`, `cleanup`, `setup_colors`, `msg`, `die`, `parse_params` |
| **Разделение потоков (stdout / stderr)** | Сообщения, логи и ошибки направляются в `stderr` (`msg >&2`), чтобы чистый вывод оставался доступен для конвейеров |
| **Задание адресации, маски и шлюза (`/etc/network/interfaces`)** | Команда `set-iface <IFACE> [--ip IP/MASK \| --ip IP --netmask MASK] [--gateway GW] [--dhcp] [--manual]`. Поддерживается как формат IPv4 с явной маской, так и CIDR-нотация |
| **Статические маршруты (персистентные при перезагрузке)** | Команды `add-route` и `del-route`. Маршруты прописываются в строфу интерфейса через директивы `up ip route add ... dev ... \|\| true` и `down ip route del ... dev ... \|\| true`, что гарантирует сохранение при перезагрузке ОС |
| **Создание сетевого моста на интерфейс** | Команда `create-bridge <BRIDGE> --ports <PORT1,PORT2...>` с параметрами IP, маски, шлюза, `bridge_ports`, `bridge_stp`, `bridge_fd` |
| **Включение и отключение интерфейсов и мостов** | Команды `up <IFACE>` и `down <IFACE>` (вызов `ifup`/`ifdown` и низкоуровневых команд ядра `ip link set dev ... up/down`) |
| **Справочная информация (`usage()`, `--help`, `-h`)** | Функция `usage()`, выводящая подробное описание синтаксиса, команд, флагов, кодов возврата и примеров |
| **Размещение в `/usr/local/bin` без расширения `.sh`** | Скрипт `install.sh` копирует утилиту в `/usr/local/bin/netconfig` с правами доступа `0755` |
| **Автоматическое резервное копирование и безопасность** | Создание копий `*.bak.<timestamp>` перед каждой модификацией конфигурационного файла, атомарная запись через временные файлы `mktemp` |
| **Режим предпросмотра (`--dry-run`)** | Флаг `--dry-run` выполняет синтаксическую валидацию и показывает действия без записи на диск и изменения состояния сети |
| **Тестирование утилиты** | Набор автоматических тестов `tests/test_netconfig.sh` (15 сьют-тестов, 100% прохождение, изоляция в `/tmp`) |
| **Подтверждающие свидетельства (evidence)** | `evidence/linux-checks.txt`, `evidence/bash-checks.txt`, `evidence/linux-result.png` |
| **Оформление отчета по ГОСТ** | Файлы `REPORT.md` и `REPORT_LR4.docx` (объем более 15 страниц, титульный лист ГУАП, 14 пт, 1.5 интервал) |

Основание: методические указания к выполнению лабораторных работ «Основы программной инженерии» (ГУАП, 2021), задание на с. 7, 15, вариант 6 на с. 18, требования к защите на с. 20.
