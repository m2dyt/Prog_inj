# Ответственность и приёмка ЛР №2

| Участник | Роль по методичке | Собственный результат | Принимает |
|---|---|---|---|
| A | Руководитель проектов в области ИТ | VM, простая установка Redmine, администратор, проект, пользователи, роли, задачи, Git и README | B и C |
| B | Специалист по информационным системам | VM, объяснение детальной установки Redmine, тема, проверка ролей, Git и README | A |
| C | DevOps-инженер | VM, Git, четыре Linux-пользователя, технический стенд, модель Git Flow | A и B |

A — Кочетков Роман; B — Энгельгард Кирилл; C — Прохоров Максим. Участники работают в своих ветках и учётных записях. Назначенные роли не являются утверждением о лично выполненных коммитах. Передача в ЛР №3: среда запускается, бэклог согласован, схема ролей ясна, требования имеют идентификаторы. Вторая работа не принимается показом готовой кассовой системы вместо организации процесса.

Доклады по 3–5 минут в порядке A/B/C. Объяснить: разницу VM и контейнера, tracker/status/workflow, репозиторий/индекс/рабочее дерево, distributed VCS, feature/release/hotfix, цели разграничения учётных записей. Выводы: повторяемое окружение снижает расхождения конфигурации; явные владельцы задач и критерии приёмки позволяют интегрировать результат команды.
