# Проверка по методическим указаниям ЛР №3

Вариант 36 на с. 66: программное обеспечение информационной системы супермаркета. Согласованная замена CGI/C++ и Apache на Python/FastAPI и Nginx не меняет проверяемые функции задания.

| Требование методички | Где выполнено |
|---|---|
| Клиент-серверная архитектура | React → Nginx → FastAPI → PostgreSQL |
| Модульный дизайн | `backend/app/routers/`, `services/`, отдельные зависимости и ошибки; компоненты и features React |
| HTML, JavaScript, CSS и интерактивность | `frontend/` |
| GET/POST и системная интеграция | `API.md`, FastAPI-маршруты, `api.js` |
| Обязательная серверная проверка данных | `schemas.py`, сервисные бизнес-правила, ограничения `init.sql` |
| Чтение и запись PostgreSQL | сервисы каталога, остатков и чеков |
| Конкретные роли БД с разными правами | `init.sql`, `DATABASE.md`, `pg_hba.conf` |
| БД по варианту | товары, чеки и необходимые связанные таблицы в `init.sql` |
| Работа примерно со 100 тыс. объектов | индексы, курсорная пагинация, `seed_large.sql`, `explain.sql` |
| Три командные роли | раздел «Роли» в `README.md` |
| Отчёт и доклад 3–5 минут | `REPORT_LR3.docx` |

Две базовые сущности «Товары» и «Чеки» дополнены строками чеков, движениями остатков, пользователями и сеансами, потому что без них нельзя обеспечить состав чека, аудит списаний и разграничение доступа. Все серверные изменения выполняются в транзакциях.

Основание: методические указания ЛР №3, задание на с. 7, требование модульности на с. 9, обязанности ролей на с. 61–62, вариант на с. 66.
