# Лабораторная работа №3 — реализация и интеграция

Участники: A — Кочетков Роман; B — Энгельгард Кирилл; C — Прохоров Максим.

Вариант 36: информационная система супермаркета. Здесь находятся прикладные исходники и схема БД. Требования и архитектура приняты на этапе ЛР №1, среда и порядок совместной работы подготовлены на этапе ЛР №2.

## 1 Запуск

В Linux VM с Docker Compose v2 и openssl:

```bash
cd 3lab
bash setup.sh
docker compose --env-file .env ps
curl --fail http://127.0.0.1:8083/api/health
```

Интерфейс: `http://127.0.0.1:8083`. OpenAPI/Swagger: `http://127.0.0.1:8083/api/docs`. Пользователи: `manager`, `cashier`, `auditor`. Их пароли сгенерированы в локальном `.env` в полях MANAGER_PASSWORD, CASHIER_PASSWORD, AUDITOR_PASSWORD. Просматривать их локально, не включать в Git и скриншоты отчёта. Они не зашиты в приложение. Токен хранится только в памяти страницы; обновление страницы требует повторного входа.

Начальная загрузка создаёт 30 полных карточек с реальными EAN-13, трёх пользователей и движения начального остатка. Для каждой позиции заданы бренд, описание, состав, КБЖУ, фотография упаковки и источник сведений; до записи в PostgreSQL bootstrap проверяет обязательные поля, уникальность и контрольную цифру каждого EAN-13. Цены и остатки учебные. Повтор bootstrap обновляет демонстрационные описания/пищевые сведения и ссылки, сохраняя существующие цены, остатки, пароли и историю. Старые неполные демо-позиции деактивируются без удаления связанных чеков. Состав, КБЖУ, GTIN и ссылки собраны в [`BARCODE_CATALOG.md`](BARCODE_CATALOG.md). Отдельный сценарий 100 тысяч объектов находится в `db/seed_large.sql`.

Используются Python 3.12, FastAPI, Pydantic 2, psycopg 3, PostgreSQL 17, React 18.3, JavaScript/JSX, PropTypes, Vite и Nginx. React 18.3 выбран для автоматических проверок PropTypes в development; в React 19 они удалены. В production дополнительная проверка JSON в `api.js` остаётся обязательной. [Разъяснение React](https://react.dev/blog/2024/04/25/react-19-upgrade-guide).

## 2 Структура и поведение

`init.sql` создаёт роли, таблицы, ограничения, индексы и триггеры; `db/10-init.sh` передаёт пароли из окружения через psql. `backend/app/main.py` только собирает FastAPI-приложение и управляет пулом. `routers/` содержит HTTP-контракты, `services/` — операции каталога, остатков и чеков, `dependencies.py` — сеанс и роли, `errors.py` — единые ответы об ошибках, `schemas.py` — Pydantic-валидацию, `security.py` — пароли и токены. `seed.py` выполняет идемпотентную начальную загрузку.

На клиенте `App.jsx` координирует состояние сценариев. `Catalog.jsx` отвечает за поиск и карточки каталога; клик по товару загружает его расширенную карточку из `GET /api/products/{id}`. `components/` содержит вход, навигацию, редактор товара и карточку с фотографией, КБЖУ, составом и построенным из EAN-13 изображением штрихкода. Показ штрихкода не запускает сканер и не меняет сценарий кассы. Текстовые сведения и URL изображения хранятся в PostgreSQL, само изображение загружается браузером по URL. Все входные свойства выделенных компонентов проверяются через PropTypes.

У роли приложения нет права менять структуру БД, удалять товарные документы или изменять пользователей. Приложение разграничивает действия пользователей отдельно от прав SQL. В конфигурации pg_hba разрешены только нужные пользователи для нужной БД; внешняя сеть закрыта. Локальный trust для postgres внутри контейнера нужен официальному entrypoint при bootstrap, не даёт удалённого входа.

Продажа двухэтапная: «Сформировать чек» фиксирует состав и цены, «Наличные получены» проводит оплату и списание в общей транзакции. Отмена применяется только к черновику. Реальный эквайринг и фискализация не реализуются. Историческая цена не меняется вслед за каталогом.

## 3 Локальная разработка без Docker

Создать отдельную PostgreSQL-БД `supermarket`, запустить `init.sql` администратором кластера. Пароли передавать переменными psql `app_password`, `admin_password`; файл не содержит готовых паролей. Для автоматизации предпочтителен включённый контейнерный bootstrap. Затем:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export DB_HOST=127.0.0.1 DB_PORT=5432 DB_NAME=supermarket DB_USER=market_app
read -rs -p 'Пароль market_app: ' DB_PASSWORD; export DB_PASSWORD
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Первичное заполнение `python -m app.seed` выполнять отдельно с DB_USER=market_admin, его паролем и тремя переменными паролей сотрудников. После bootstrap API запускается только под market_app. Для frontend — Node 22.12+:

```bash
cd frontend
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Vite проксирует `/api` в localhost:8000, поэтому не нужен CORS `*`. Production: `pnpm build`. Lockfile обязателен. Приложение не зависит от файлов `1lab` и не использует заглушку `2lab`.

## 4 Демонстрация

1. Войти менеджером; создать карточку с уникальным кодом; добавить остаток с основанием.
2. Войти кассиром; найти товар по названию/штрихкоду; добавить в корзину; сформировать чек.
3. Проверить серверную сумму и подтвердить наличные; в истории открыть оплаченный чек.
4. Повторить запрос оплаты: остаток не должен уменьшиться второй раз.
5. Создать два черновика на последний экземпляр; одновременная оплата завершает только один.
6. Продемонстрировать 422 на отрицательную цену/дробное количество, 403 на изменение товара кассиром, запрет отмены оплаченного чека.

## 5 Проверки и эксплуатация

См. `TESTING.md`, `DATABASE.md`, `API.md`. Фактические результаты текущей подготовки — `../VERIFICATION.md`; числа производительности не подменяются целевыми значениями из требований. `docker compose down` сохраняет том. Для обновления исходников — `docker compose up -d --build`; перед изменением схемы сначала резервная копия и миграция. `init.sql` предназначен для свежей БД, а не для повторного применения поверх рабочих данных.

Пакет является учебной версией. Для внешней эксплуатации нужны TLS, отдельный процесс управления сотрудниками, регламент мониторинга, резервного копирования и ротации секретов. Приложение слушает localhost по умолчанию. Swagger подгружает UI-ресурсы с CDN; сама схема `/api/openapi.json` доступна без CDN.
