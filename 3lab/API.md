# Контракт API

Базовый путь `/api`. Защищённые методы требуют `Authorization: Bearer TOKEN`. Токен выдаётся POST `/auth/login`, сохраняется на сервере в виде SHA-256 и действует 8 часов. POST `/auth/logout` отзывает текущую сессию; GET `/auth/me` возвращает идентификатор, имя и роль. Пароль проверяется scrypt с индивидуальной солью. Лимит попыток входа настроен в Nginx, API не опубликован напрямую.

| Метод и путь | Роль | Результат |
|---|---|---|
| GET `/health` | Без входа | Проверка соединения с БД |
| POST `/auth/login` | Без входа | access_token, token_type, expires_at |
| GET `/auth/me` | Любая | Текущий сотрудник |
| POST `/auth/logout` | Любая | 204, токен отозван |
| GET `/products` | Любая | items и next_cursor |
| GET `/products/{id}` | Любая | Полная карточка: бренд, описание, состав, КБЖУ на 100 г, EAN, URL фотографии и источник |
| POST `/products` | manager | 201, созданная карточка с stock=0 |
| PUT `/products/{id}` | manager | Полная карточка с новым version |
| POST `/products/{id}/stock` | manager | Новый остаток и версия |
| POST `/receipts` | cashier, manager | 201, черновик или прежний результат ключа |
| GET `/receipts` | Любая | Страница истории; для кассира только собственные |
| GET `/receipts/{id}` | По правам чтения | Чек, строки, итог |
| POST `/receipts/{id}/pay` | cashier, manager | Оплаченный чек с сохранённым способом; повтор безопасен |
| POST `/receipts/{id}/cancel` | cashier, manager | Отменённый черновик |

Каталог: `q` — подстрока названия от 3 символов либо полный цифровой штрихкод длиной 8–14; `category` — точное название категории; `after` — предыдущий ID, по умолчанию 0; `limit` — 1–100, по умолчанию 24; `include_archived=true` доступен менеджеру. Порядок всегда по ID ASC. Для истории — `before` и ID DESC. `next_cursor=null` означает конец. Пагинация не представляет снимок БД между запросами: параллельные вставки или изменения могут изменить видимый набор, но offset-смещения нет.

Пример создания карточки:

```json
{"barcode":"4601234567890","name":"Молоко 1 л","category":"Молочные продукты","price":"99.90"}
```

При PUT передаются те же поля, `active` и текущий `version`. Начальный остаток 0; корректировка выполняется отдельно:

```json
{"delta":10,"reason":"Учебное поступление"}
```

Создание чека (ID товара взять из реального GET/POST):

```json
{"request_id":"78c9bf7f-06e5-451a-a81a-e528537296e8","items":[{"product_id":1,"quantity":2}]}
```

Цена, итог, статус, автор, ID чека и paid_at не принимаются от клиента. Неизвестные поля запрещены. Повтор с тем же request_id и тем же составом возвращает тот же документ, в том числе если он уже завершён. При неизвестном исходе запроса нельзя автоматически генерировать другой UUID.

Оплата черновика требует способ и данные, относящиеся только к нему:

```json
{"payment_method":"cash","cash_received":"1000.00"}
```

```json
{"payment_method":"card_simulated"}
```

Наличные должны покрывать серверный итог; иначе API вернёт 422, чек останется черновиком, а остаток не изменится. Для наличных ответ содержит `cash_received` и вычисленную сервером `change_due`. Для карты `card_simulated` не передаются реквизиты карты: это локальная учебная симуляция; `card_outcome: "declined"` позволяет показать отказ терминала (402), не списывая остаток. Успешная оплата сохраняется вместе с чеком и показывается в его деталях.

Сервер возвращает цены/суммы строками Decimal (`"199.80"`), даты — ISO 8601 с часовым поясом. Корзина браузера имеет только предварительную сумму. Гарантия исторической цены начинается после создания серверного чека.

Ошибки валидации имеют `detail: [{loc, msg, type}]` без исходного тела и пароля. Бизнес-ошибки имеют `detail: "сообщение"`. 409 не повторяют бесконечно: нужно обновить данные или отменить черновик. 503 при блокировке допускает повтор того же идентификатора. 401 означает необходимость повторного входа.
