## Быстрый запуск внутри Linux VM

Предварительно выполнить `VM_SETUP.md`: установить Docker Engine с Compose v2, Git, openssl. Команды выполняются из `2lab`:

```bash
bash setup.sh --check
bash setup.sh --with-redmine
docker compose --env-file .env ps
curl --fail http://127.0.0.1:8082/api/health
```

Страница стенда: `http://127.0.0.1:8082`; Redmine: `http://127.0.0.1:8085`. `--check` создаёт отсутствующий `.env`, проверяет Docker и Compose, но не запускает контейнеры. `--with-redmine` добавляет независимый контур Redmine. `--help` не требует Docker.

Первый запуск генерирует случайные пароли и сохраняет их с ограниченными правами; последующие запуски сохраняют `.env` и тома. Изменение пароля в `.env` после инициализации не меняет пароль в существующей БД: его изменяют SQL-командой и синхронизируют конфигурацию. `docker compose down` останавливает сервисы и сохраняет данные. `down -v` удаляет данные и не используется для обычного обновления.

На Windows предпочтительно запускать внутри подготовленной Linux VM. Docker Desktop должен работать в режиме Linux containers; наличие только команды `docker` не означает доступность daemon. Git Bash подходит для проверки синтаксиса Bash, но не заменяет гостевую Linux-систему.

## Разделение этапов

Имя Compose-проекта — `supermarket-lab2`, база — `supermarket_env`, HTTP — 8082. В API нет карточек товаров, чеков, ролей приложения и операций продажи. Наличие PostgreSQL проверяется его healthcheck. Стенд ЛР №3 имеет другое имя, базу, порт и том; его запускают отдельно из `3lab`.

В методичке ЛР №2 на с. 7 также описан этап II разработки. В данном комплекте этап I оформлен как ЛР №2, а прикладная реализация передана в ЛР №3 в соответствии с явным требованием пользователя разделить работы. Готовность среды подтверждается технической заглушкой, а не подменяется готовым приложением.
