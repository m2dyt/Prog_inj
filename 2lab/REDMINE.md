# Настройка Redmine для проекта supermarket-36

Redmine развёртывается как готовая система управления проектом из официального контейнерного образа. В репозитории нет расширений Redmine и сценариев, изменяющих внутренние модели платформы. Одноразовые глобальные параметры задаются через веб-интерфейс администратора; проектные данные, для которых Redmine предоставляет REST API, создаёт `provision_redmine.py`.

## 1. Запуск и первый вход

Из каталога `2lab` выполнить `bash setup.sh --with-redmine`. Контур `supermarket-redmine` использует отдельную PostgreSQL и не содержит предметную базу супермаркета. Открыть `http://127.0.0.1:8085`, войти стандартной учётной записью администратора и сразу заменить стандартный пароль в разделе «Моя учётная запись».

Одноразовые административные настройки и автоматическое наполнение проекта разделены. Последовательность первичной настройки:

1. В разделе «Администрирование → Настройки» задать язык, часовой пояс и отключить почтовые уведомления для учебного стенда.
2. Создать роли, трекеры, статусы и workflow из таблиц ниже.
3. Включить REST API: «Администрирование → Настройки → API → Включить REST API».
4. Из `2lab` выполнить `python3 provision_redmine.py --dry-run`, затем `python3 provision_redmine.py --apply`.
5. Проверить проект, участников, 15 задач и связи; сохранить собственные снимки страниц проекта, участников, workflow и списка задач.

Скрипт использует официальный REST API и только стандартную библиотеку Python. Он сам создаёт проект `supermarket-36` с точным названием и закрытым доступом (если проект уже существует — исправляет название/публичность), недостающие учётные записи, членство с ролями, категории backlog, 15 задач и связи `follows` по столбцу `Depends on`. Повторный запуск безопасно пропускает уже созданные задачи по маркеру `External ID`. Для новых пользователей создаются случайные временные пароли: скрипт печатает их один раз в терминал после создания и требует сменить при первом входе; пароль уже существующей учётной записи он не меняет. Адреса вида `@supermarket36.invalid` — фиктивные и не предназначены для почты. Ключ API администратора вводится скрыто; не помещайте его в CSV, командную строку или Git.

У Redmine нет REST-операций создания ролей и прав; `/roles`, `/trackers`, `/issue_statuses` и `/custom_fields` предоставляют определения для чтения. Поэтому создание/переименование глобальных ролей, трекеров, статусов, workflow и пользовательских полей остаётся разовой настройкой в веб-интерфейсе администратора. Скрипт сверяет наличие нужных значений и останавливается с понятной ошибкой, если обязательная настройка отсутствует. В текущем стенде он понимает уже заведённые имена `Manager`/`Developer`/`devops`, `req`/`task`/`error` и статус `New` как соответствия ролям и значениям из CSV. Пользовательские поля `External ID`, `Depends on`, `Requirement`, если они ещё не заведены, сохраняются в описании задачи вместе с постоянным маркером `External ID`; при наличии полей скрипт также заполняет их отдельно.

Глобальное администрирование Redmine остаётся только у отдельной учётной записи администратора.

## 3. Трекеры, статусы и категории

Трекеры: `Требование`, `Задача`, `Ошибка`. Скрипт понимает также текущие английские имена-алиасы `req`, `task`, `error`. Категории он создаёт по значениям CSV (сейчас их семь), поэтому вручную создавать категории не нужно.

Статусы:

| Статус | Назначение |
|---|---|
| Новая | задача поставлена и ещё не принята исполнителем |
| В работе | исполнитель выполняет задачу |
| На проверке | результат передан другому участнику |
| Требует исправления | проверяющий вернул результат с замечаниями |
| Закрыта | критерии приёмки выполнены |

## 4. Workflow

Настроить переходы отдельно для каждой проектной роли. Базовая последовательность: `Новая → В работе → На проверке → Закрыта`. Из `На проверке` разрешить переход в `Требует исправления`, а затем — только во `В работе`. Прямые переходы из `Новая` или `В работе` в `Закрыта` запретить.

| Роль | Новая → В работе | В работе → На проверке | На проверке → Требует исправления | На проверке → Закрыта | Требует исправления → В работе |
|---|:---:|:---:|:---:|:---:|:---:|
| Руководитель проекта | да | да | да | да | да |
| Аналитик-разработчик | да | да | да | нет | да |
| DevOps-инженер | да | да | да | нет | да |

Закрытие выполняет руководитель после проверки результата другим участником. Для учебного проекта это правило фиксируется также в описании задач и протоколе приёмки.

## 5. Поля и импорт 15 задач

Файл `backlog.csv` сохранён в UTF-8 с BOM и содержит 15 задач. При использовании API-скрипта пользовательские поля `External ID`, `Depends on`, `Requirement` необязательны: при их отсутствии значения попадают в описание задачи, где всегда остаётся маркер `External ID` для безопасного повторного запуска. Если преподаватель требует эти поля в отдельных колонках, создайте три текстовых поля через UI администратора до запуска.

Рекомендуемый способ — `python3 provision_redmine.py --apply`: скрипт создаёт задачи через REST API и сразу назначает исполнителей, категории, оценки, статусы, трекеры и связи. Если преподавателю нужен именно штатный CSV-импорт, откройте «Задачи → меню → Импорт», выберите CSV, кодировку UTF-8, разделитель-запятую и первую строку как заголовок. Сопоставьте:

| CSV | Поле Redmine |
|---|---|
| Subject | Тема |
| Tracker | Трекер |
| Status | Статус |
| Priority | Приоритет |
| Assigned to | Назначена |
| Estimated time | Оценка времени |
| Description | Описание |
| Category | Категория |
| External ID / Depends on / Requirement | одноимённые пользовательские поля |

`External ID` (`SM-01`…`SM-15`) — проектный ключ. При штатном импорте `Depends on` содержит эти ключи, но импорт текста не создаёт связи «предшествует/следует»; их надо добавить вручную. Скрипт `provision_redmine.py` создаёт связи автоматически. Перед повторным ручным импортом проверьте существующие `External ID`, чтобы не получить дубликаты.

## 6. Проверка скрипта

Запускайте команды из каталога `2lab` в Ubuntu VM:

```bash
python3 provision_redmine.py --dry-run
python3 provision_redmine.py --apply
```

Для `--apply` в Redmine должен быть включён REST API. Скрипт спросит API key скрытым вводом; его можно посмотреть на странице «Моя учётная запись». В режиме без `--apply` сеть и Redmine не затрагиваются. Если выполнение оборвалось после части запросов, запустите его ещё раз: существующие аккаунты и задачи повторно не создаются, пароль существующего пользователя не сбрасывается.
