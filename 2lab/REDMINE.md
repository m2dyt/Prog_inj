# Настройка Redmine для проекта supermarket-36

Redmine развёртывается как готовая система управления проектом из официального контейнерного образа. В репозитории лабораторной нет кода расширений Redmine и нет сценариев, работающих с его внутренними моделями. После запуска все учебные сущности создаются через веб-интерфейс, как показано в методических указаниях.

## 1. Запуск и первый вход

Из каталога `2lab` выполнить `bash setup.sh --with-redmine`. Контур `supermarket-redmine` использует отдельную PostgreSQL и не содержит предметную базу супермаркета. Открыть `http://127.0.0.1:8085`, войти стандартной учётной записью администратора и сразу заменить стандартный пароль в разделе «Моя учётная запись».

Последовательность ручной настройки:

1. В разделе «Администрирование → Настройки» задать язык, часовой пояс и отключить почтовые уведомления для учебного стенда.
2. Создать закрытый проект `supermarket-36` с названием «Информационная система супермаркета».
3. Создать роли, трекеры, статусы и workflow из таблиц ниже.
4. Добавить пользователей `student_a`, `student_b`, `student_c` и назначить их проектные роли.
5. Импортировать `backlog.csv`, проверить 15 задач и вручную добавить связи предшествования по полю `Depends on`.
6. Сохранить собственные снимки страниц проекта, участников, workflow и списка задач.

Глобальное администрирование Redmine остаётся только у отдельной учётной записи администратора.

## 3. Трекеры, статусы и категории

Трекеры: `Требование`, `Задача`, `Ошибка`. Категории: `Аналитика`, `Инфраструктура`, `Разработка`, `Тестирование`, `Документация`.

Статусы:

| Статус | Назначение |
|---|---|
| Новая | задача поставлена и ещё не принята исполнителем |
| В работе | исполнитель выполняет задачу |
| На проверке | результат передан другому участнику |
| Требует исправления | проверяющий вернул результат с замечаниями |
| Закрыта | критерии приёмки выполнены |

## 4. Workflow

Настроить переходы отдельно для каждой проектной роли. Базовая последовательность: `Новая → В работе → На проверке → Закрыта`. Из `На проверке` разрешить переход в `Требует исправления`, а затем — только во `В работе`. Прямые переходы из `Новая` или `В работе` в `Закрыта` запретить.

| Роль | Новая → В работе | В работе → На проверке | На проверке → Требует исправления | На проверке → Закрыта | Требует исправления → В работе |
|---|:---:|:---:|:---:|:---:|:---:|
| Руководитель проекта | да | да | да | да | да |
| Аналитик-разработчик | да | да | да | нет | да |
| DevOps-инженер | да | да | да | нет | да |

Закрытие выполняет руководитель после проверки результата другим участником. Для учебного проекта это правило фиксируется также в описании задач и протоколе приёмки.

## 5. Импорт 15 задач

Файл `backlog.csv` сохранён в UTF-8 с BOM и содержит 15 задач. До импорта создать текстовые пользовательские поля `External ID`, `Depends on`, `Requirement`.

Открыть «Задачи → меню → Импорт», выбрать CSV, кодировку UTF-8, разделитель-запятую и первую строку как заголовок. Сопоставить:

| CSV | Поле Redmine |
|---|---|
| Subject | Тема |
| Tracker | Трекер |
| Status | Статус |
| Priority | Приоритет |
| Assigned to | Назначена |
| Estimated time | Оценка времени |
| Description | Описание |
| Category | Категория |
| External ID / Depends on / Requirement | одноимённые пользовательские поля |

`External ID` (`SM-01`…`SM-15`) — проектный ключ. `Depends on` содержит эти ключи для последующего ручного создания связей «предшествует/следует»; сам импорт текста связь не создаёт. Перед повторным импортом проверить существующие `External ID`, чтобы не получить дубликаты.

## 6. Контроль результата

Проверить:

- закрытый проект и ровно три участника;
- три трекера, пять статусов и заданные переходы workflow;
- ровно 15 задач с исполнителями, оценками и критериями приёмки;
- запрет проектным пользователям открывать глобальное администрирование;
- отсутствие прямого закрытия задач из начального состояния;
- назначение индивидуальной ЛР №4 Роману Кочеткову.

Фактические снимки ранее настроенного стенда находятся в `evidence/redmine-issues.png` и `evidence/redmine-members.png`. Файл `evidence/redmine-checks.json` фиксирует проверенные количества. Он служит свидетельством, а не сценарием изменения Redmine.
